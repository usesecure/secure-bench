# Phase 12: prospective methodology repair

Phase 12 advances the prospective Secure Bench behavior to version 0.2.0. It repairs the benchmark
and adapter defects confirmed by the public Phase 11 postmortem without altering any Phase 0–11
evaluator, fixture, result, report, ledger, taxonomy, or diagnostic artifact. The official Phase 10
score remains historically unchanged and was not rescored.

This phase did not execute a scanner, inspect Secure Engine source, or create an unseen holdout. The
new corpus is disclosed development regression material. Its validation is described as validated,
classified, or contract-conformant; it is not described as scanner detection.

Phase 12 does not support public rankings, scanner comparisons, superiority claims,
production-readiness claims, or complete-coverage claims.

## Root causes repaired

The Phase 11 causal analysis confirmed three benchmark-owned defects relevant to prospective work:

1. The Phase 10 adapter reconstructed semantics from generic evidence and ignored a complete
   declared `evidence_contract_v2` projection.
2. Phase 9 expectations could drift from the already-frozen canonical taxonomy.
3. Direct fixtures used an unrelated or undefined value at the sink, and paired controls could not
   prove that their barrier protected the value under evaluation.

The 0.2.0 implementation addresses these causes without scanner-specific aliases, rule exceptions,
fixture identifiers, or score repairs.

## Adapter precedence

The declared Evidence Contract v2 projection is the primary scoring input. The adapter preserves
the exact taxonomy tuple, primary CWE, source and sink identity, portable spans, ordered path,
connected edges, transforms, value continuity, guards, sanitizers, effective barriers,
authorization and dominance effects, uncertainty, unresolved-call state, and duplicate
fingerprint.

Generic report evidence, prose, scanner rule identifiers, and tool identity are non-authoritative.
They cannot replace declared v2 evidence. This reproduces the Phase 10 defect condition in a public
synthetic test: an exact v2 projection remains exact even when an unusable generic evidence path is
present.

A compatibility projection is accepted only when:

- the v2 projection is absent;
- the caller explicitly selects the versioned legacy route; and
- the separately typed legacy projection is complete and canonical.

If both projections are declared, they must be byte-semantically equivalent after typed parsing.
Conflicts fail closed. A malformed, incomplete, version-mismatched, or taxonomy-invalid v2 object
also fails closed and cannot fall back to legacy normalization.

Report adjudication precedes process-status interpretation. A valid report associated with a
normal findings exit remains authoritative under the existing public process-status policy; adapter
matching does not infer crashes from exit codes.

## Frozen taxonomy binding

Every prospective expectation is generated by resolving its family category through the committed
taxonomy `1.0.0`. The generator copies the canonical category, invariant, and primary CWE from that
artifact. Authoring and verification reject a different taxonomy version, unknown category,
category/invariant mismatch, primary-CWE mismatch, or any mutation of those coordinates.

The Phase 9 expectations and Phase 10 result remain unchanged. Corrected prospective expectations
exist only in the Phase 12 public manifest.

## Public regression corpus

The corpus contains 28 vulnerable/control pairs and 56 cases in 70 source files. Each SE1001–SE1007
family has four pairs. Each framework, language, and topology has seven pairs:

| Dimension | Values | Pairs per value | Cases per value |
| --- | --- | ---: | ---: |
| Family | SE1001–SE1007 | 4 | 8 |
| Framework | Node.js, Express, Next.js App Router, Server Actions | 7 | 14 |
| Language | JavaScript, JSX, TypeScript, TSX | 7 | 14 |
| Topology | direct, helper-mediated, inter-file aliased, control-flow-sensitive | 7 | 14 |

Every vulnerable case has an exact source, sink, ordered connected path, stable concrete value
identity, and no effective barrier. Every paired control protects that same value with a terminating
barrier that dominates the same sensitive operation. Forward mutations insert only the declared
family-specific protection; inverse mutations restore the committed vulnerable fingerprint.

Validation rejects disconnected direct flows, undefined or unrelated values, barriers over another
value, nonterminating barriers, taxonomy drift, invalid spans, missing edges, duplicate identities,
duplicate case fingerprints, nonportable paths, privacy violations, and matcher-owned terminology
inside scanner-visible fixture paths or source.

## Prospective holdout authoring

The public `holdout-authoring-v1` contract defines the later Phase 13 lifecycle without creating its
materials. Before sealing, a future author must validate exact spans, connected values, taxonomy,
barriers, inverses, licenses, provenance, duplicates, privacy, leakage, and deterministic
reconstruction. Public pre-execution summaries may expose aggregate design counts and commitment
hashes only, never case assignments or answers.

The later lifecycle must commit the taxonomy, evidence contract, evaluator, adapter and process
policies, fixture hashes, aggregate corpus hash, Merkle root, manifest hash, and genesis-ledger hash.
It requires counterbalanced assignments, fresh read-only cases, blocked outbound network access,
explicit resource limits, one execution per eligible case, append-only failure accounting, and no
reruns. After its designated lifecycle, the holdout must be retired and disclosed; subsequent use is
development regression rather than an unbiased examination.

Phase 12 contains no Phase 13 fixture, answer, manifest, or ledger.
